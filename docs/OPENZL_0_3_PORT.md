# OpenZL 0.3.0 JNI port review

Release: `0.3.0-1`. Upstream tag: `v0.3.0`, commit
`32246b48faee46807f84183dac4db479089f5445`.

References: [upstream release notes](https://github.com/meta/openzl/releases/tag/v0.3.0),
[source changes since 0.2.0](https://github.com/meta/openzl/compare/v0.2.0...v0.3.0).

| Upstream change | JNI accommodation |
| --- | --- |
| Faster LZ engine and LZ training | `LZ` profile; reusable trained candidates |
| Numeric Compression Transformer | `NUMERIC` at level 7+; explicit `TRANSFORMER_NUMERIC` graph |
| Sparse numeric streams | Exercised through numeric selectors, including zero-heavy and extreme-value inputs |
| Dictionary bundles | `TrainedCompressor`, `trainCandidates`, `configureTrained`, `setDictionaryBundle` |
| Serializable brute-force selector | `configureBruteForce` uses the new builder; binary save/reload regression |
| Training controls | Candidate limit, target format and existing whole-ACE time budget |
| Frame version 27, previously 24 | Default 27; explicit 24 compatibility; two-version JVM tests |
| Big-endian integer profiles and SDDL2 additions | Java profiles and round-trip/invalid-schema tests |
| ARM kernels and xxHash update | Supplied by pinned upstream; licenses checked against sources |

## Binding defects fixed during the port

- Compression contexts previously masked compressor-level format and level settings.
- Protobuf's upstream context forced format 27 even for a format-24 trained graph.
  An idempotent CMake patch removes that context override. Training and conversion
  now retain the selected target format.
- Automatic Protobuf training lacked the required compressor generator. It now
  registers dependencies, restores candidates, and bounds its ACE work to one
  second with one worker. A regression checks that the initial graph is actually
  replaced and that frames from before and after training remain readable.
- Upstream crowding-distance pruning requires six points. Positive Java result
  limits below six use six internally and trim the returned results, preserving
  upstream order. Limits therefore include one, rather than failing at runtime.
- Metadata inspection and Protobuf conversion allocated Java objects while holding
  pinned arrays. Metadata now unpins before allocation; Protobuf copies and unpins
  before conversion or training. Legacy compression helpers also retain saved
  parameters and use scoped native contexts.
- Pooled contexts now drop custom graphs and dictionary references on close.
  Thread-local caches own their contexts, releasing them when worker threads exit,
  and the shared JNI handle-field cache uses atomic access.
- Profile construction forwards an explicitly selected compression level, including
  the SAO profile's level-7 Transformer branch.

## Validation

See the [expanded validation report](VALIDATION_0_3_0_1.md) for clean builds,
sanitizers, the Java runtime matrix, stress results and guard defects fixed.

`TestOpenZL03Compatibility` covers default/legacy frame versions, parameter
persistence, LZ training, all six big-endian profiles and SDDL2 annotations.
`TestOpenZL03Training` adds dictionary persistence, separate decoding, failed-load
recovery, defensive copies, 200 concurrent-instance round trips, candidate limits,
Transformer integer/float bit patterns and brute-force graph serialization.
`TestOpenZL03ProtobufTraining` covers automatic training and emitted target format.

The complete Maven reactor runs with Java native-call checks enabled. The
`scripts/check_frame_compatibility.py` harness uses finished release JARs in
separate JVMs to exchange byte-array, direct-buffer and numeric frames with the
published JNI 0.2.0-1 artifact (native OpenZL 0.2.0), verified by pinned JAR checksums. It also checks old trained
graphs, newly trained format-24 byte/Protobuf frames, and dictionary persistence
across JVMs. The old reader must reject the default format 27.

Source, base, Javadoc and each platform archive are checked for full license texts
and actual native binaries. The post-cleanup CI run passed all 209 unit tests
with zero failures, errors or skips on Linux x86_64, macOS ARM64 and Windows
x86_64. The release gate additionally runs the boundary/corruption stress harness
on all three platforms with JNI checking enabled. Local Linux runs do not
substitute for those platform jobs.

## Deliberate API scope

The existing Protobuf-specific `byte[][]` training API remains self-contained and
rejects dictionary training. Dictionary candidates are available through the
general compressor API. Protobuf conversion does not yet expose a dictionary
loader. The optional codec output cache and custom materializer registration are
also outside this Java API. Existing multi-input API work is separate from this
upstream upgrade.

Serialized numeric graphs generated by 0.3.0 require a 0.3.0 reader, even when
their compressed frames target version 24. Persist dictionaries together with
the graph; dictionary-backed frames require format 25 or newer.
